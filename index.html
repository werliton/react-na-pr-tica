  Bloco 4 · Hooks customizados
  
Custom hook: reaproveitar lógica com estado

  

    
function useToggle(inicial = false) {
  const [on, setOn] = useState(inicial);
  const toggle = () => setOn(v => !v);
  return [on, toggle];
}

// em qualquer componente:
const [aberto, alternar] = useToggle();

    

      
Dois componentes, a mesma lógica, estados independentes:

      
Menu: fechado

      
Modo escuro: desligado

    

  

  
Instrutor: regra: o nome começa com “use” e só pode chamar hooks no topo da função. Compartilha lógica, não estado.

  Bloco 5 · Context API
  
createContext + Provider + useContext

  

    
const UserCtx = createContext();

function Provider({ children }) {
  const [user, setUser] = useState('Ana');
  return (
    <UserCtx.Provider value={{ user, setUser }}>
      {children}
    </UserCtx.Provider>
  );
}

// em qualquer filho:
const { user } = useContext(UserCtx);

Instrutor: Context é ótimo para dados de baixa frequência (tema, usuário, idioma). Para estado global complexo ou muito dinâmico, existem Zustand e Redux Toolkit; cite-os sem aprofundar.

  Bloco 6 · fetch + useEffect
  
Toda requisição tem três estados

  

    

      

        
        
      

      
idle: nada pedido ainda

    

    
const [dados, setDados] = useState(null);
const [loading, setLoading] = useState(true);
const [erro, setErro] = useState(null);

useEffect(() => {
  fetch('/api/usuario')
    .then(r => r.ok ? r.json() : Promise.reject())
    .then(setDados)
    .catch(() => setErro('Falha'))
    .finally(() => setLoading(false));
}, []);

  

  
Instrutor: peça para a turma nomear os três estados (loading, erro, sucesso) antes de clicar. Erro comum: esquecer de tratar r.ok, pois fetch só rejeita em falha de rede.





  Bloco 6 · Race condition
  
Cleanup: a resposta antiga não pode vencer

useEffect(() => {
  let ignorar = false;

  Bloco 7 · Cache de dados
  
Cache: não pergunte duas vezes a mesma coisa

  

    

      

        
        
      

      

      
Escolha um usuário

      
Cache atual: vazio

    

    
const cache = new Map();

async function buscar(id) {
  const hit = cache.get(id);
  if (hit && Date.now() - hit.t < TTL)
    return hit.dados;      // HIT

  const dados = await api(id);  // MISS
  cache.set(id, { dados, t: Date.now() });
  return dados;
}

  

  
Instrutor: clique no mesmo usuário duas vezes: o segundo é instantâneo (HIT). Espere 15s ou invalide para voltar ao MISS. Discuta o risco de dado desatualizado: por isso existem TTL e invalidação.





  Bloco 7 · Bibliotecas
  
Não reinvente: loading, erro, cache e cleanup prontos

  

    

      
TanStack Query
Cache, revalidação, retry e invalidação. Padrão de mercado para dados de servidor.

      
SWR
Mais enxuta, baseada em stale-while-revalidate: mostra o cache e atualiza em segundo plano.

      
RTK Query
Camada de dados do Redux Toolkit, ideal se o app já usa Redux.

    

    
const { data, isLoading, error } =
  useQuery({
    queryKey: ['usuario', id],
    queryFn: () => buscar(id),
    staleTime: 15_000,
  });

// loading, erro, cache, cleanup
// e race condition: tudo tratado
